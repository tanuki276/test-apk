# アカウントと履歴復元

## 使い方
設定からメールアドレスとパスワードで「登録して履歴を引き継ぐ」を選びます。
ゲストのUIDにメール認証をリンクするため、既存の履歴のパスは変わりません。
アプリの再インストール後は同じメールアドレスとパスワードで「ログイン」すると履歴を読み込めます。
すでにアプリを消してゲストの認証情報を失った場合、その履歴をこの機能から復元することはできません。

登録済みアカウントへのログインでは、別のFirebaseアプリでログイン先を検証し、主アプリをゲストのまま保って本人の履歴を200件ずつコピーします。
コピー先が保存を確認した後に元のゲスト履歴を削除し、最後に主アプリを登録アカウントへ切り替えます。
コピー先のIDはゲストUIDと元のドキュメントIDから固定生成し、通信中断後の再試行でも重複させません。
途中で失敗した場合は同じアカウントへのログインを再試行します。移行済みの履歴は移行先、未完了分はゲスト側にあります。
パスワードは入力欄の自動保存を無効にし、アプリ独自のファイルやログに保存しません。

## 有効化に必要な設定
Firebase Console → Authentication → Sign-in method で「メール/パスワード」を有効にしてください。
既存の匿名認証も引き続き有効にします。アプリの依存・Firebaseプロジェクト設定は既存のものを使用します。
パスワードポリシーや再設定メールのテンプレート・送信元も確認してください。
本作業では本番Firebase Consoleの設定変更、メール送信、実ユーザーの登録や削除は行っていません。

## 削除
設定に「アカウントと履歴を削除」を追加しました。再認証後に本人の履歴を200件ずつ削除し、最後に認証アカウントを削除します。
履歴削除途中の通信失敗では一部削除される可能性があることを表示し、再試行できます。
履歴画面には全削除ボタンを追加していません。
ストア提出前にアプリ外の削除依頼窓口・公開URLを用意してください。

## 検証
Firebase Auth / Firestoreエミュレーターの3テストが成功。匿名UIDを維持した登録、別セッションからのログイン・履歴復元、移行先へのコピー、アカウント削除を検証しました。これはFirebase SDKとRulesの結合検証で、Android UI操作の実機テストは未実施です。
実機では登録→履歴生成→ログアウト→ログイン、およびアプリ削除→再インストール→ログインを確認してください。
処理中の回転・バックグラウンド復帰、誤ったパスワード、既存メールでの登録、オフライン中断後の再試行も確認項目です。
