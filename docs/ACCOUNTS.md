# アカウントと履歴の引き継ぎ

## 使い方
- 初めて使う方：設定のメールアドレス・パスワードを入力して「登録して履歴を引き継ぐ」を選びます。匿名UIDにメール認証をリンクし、ゲスト時の履歴をそのまま使えます。
- 登録済みの方：「ログインして履歴を引き継ぐ」を選びます。ログイン先の保存済み履歴と、現在のゲスト履歴をまとめて表示します。元の履歴を上書きしません。
- 再インストール後：登録したメールアドレスとパスワードでログインしてください。クラウドに保存済みの履歴を再び表示できます。
- パスワードを忘れた方：メールアドレスを入力して「パスワードを忘れた場合」を選びます。

アプリを削除する前にメール登録してください。未登録のままアンインストール・データ消去を行い認証情報を失ったゲスト履歴は、本人を特定できないため復元できません。調理設定は端末内の保存で、再インストール後には戻りません。
復元コードの発行・入力・表示機能は廃止しました。旧版でコードを発行済みでも、現在のゲストセッションが残っていればメール登録・ログイン時に履歴を移せます。旧コードだけを持ち、認証セッションを失っている場合のコード復元は提供しません。

## 引き継ぎ処理
ログイン先を別のFirebaseアプリで検証し、主アプリはゲスト認証を維持して履歴を200件ずつコピーします。コピー先の保存確認後に元のページを削除し、全ページの処理後にログイン先へ切り替えます。
コピー先はゲストUIDと元ドキュメントIDによる固定IDとし、中断後の再試行で重複しないようにします。失敗時はゲストのまま、同じメールアドレスで再試行してください。移行済みの履歴は移行先、未完了分はゲスト側に保存されています。履歴を引き継がずにログインする操作は廃止しました。
旧版の認証資格で利用中のゲストは、新規メールアカウントを作成して同じ手順で移します。移行が途中で失敗した場合、新規登録済みのメールで「ログインして履歴を引き継ぐ」を再試行してください。新版の起動時に端末の旧コードを消去します。Firebaseの既存認証セッションは移行のため維持します。
パスワードは入力欄の自動保存を無効にし、アプリ独自のファイルやログには保存しません。

## 有効化に必要な設定
Firebase Console → Authentication → Sign-in method で「メール/パスワード」と「匿名」を有効にしてください。パスワードポリシーや再設定メールの送信元も確認してください。本作業では本番Firebaseの設定変更は行っていません。

## 削除
設定の「アカウントと履歴を削除」でパスワードによる再認証後、本人の履歴を200件ずつ削除し、最後に認証アカウントを削除します。失敗時は一部削除される場合があるため再試行してください。

## 検証
Android計装テストに、登録後の再ログイン、205件のゲスト履歴と既存履歴の統合、再インストール相当のセッション再作成、誤パスワード時のゲスト維持、通信失敗後の再試行、ログアウト直後のボタン操作、旧版ゲストからの移行を用意しています。
実端末でのアンインストール・再インストールは別途確認してください。
