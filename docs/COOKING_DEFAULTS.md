# 調理の事前設定とUI更新（Version 1.4）

設定の「いつもの調理設定」からアレルギー・避けたい食材、使える調味料、使える調理方法を保存します。
端末内のアプリ専用領域にアカウント別で保存し、次回以降の生成時に自動で追加します。未入力は指定なし、「なし」は使用しない条件として区別します。
匿名ユーザーを登録する場合は同じUIDなので設定をそのまま維持します。既存アカウントへログインする場合は、移行先の端末内設定が未登録の場合だけゲストの設定を引き継ぎます。
ログアウトしても同じ端末の登録アカウントの設定は残り、アカウント削除時には消去します。再インストール時のクラウド復元は履歴のみで、事前設定は端末内保存です。

生成指示では、登録したアレルギーを「食材をすべて使う」・追加指示より優先するよう指定します。調味料と調理方法は登録範囲内に限定し、不足食材の追加を避ける条件を付けています。
これはAIへの制約であり、アレルギーの安全性を保証するものではありません。設定画面にも原材料等の確認案内を表示しています。

予算・各選択欄の自由指定をUI、入力処理、関連文字列から削除しました。補足は追加指示に集約しています。過去の履歴本文は変更しません。
UIは深いグリーンと落ち着いた背景に統一。ネイティブの線画ベクターアイコン、余白、カード、選択欄を再設計し、絵文字は使っていません。

## 検証
- JVM: 保存内容から生成条件を組み立てる処理、空欄/なしの区別、長さ制限とアレルギー優先をテスト。
- API 36エミュレーター: 文字サイズ130%で画面起動、設定入力・保存と画面再作成、ユーザー別の保存、長いレシピの末尾へのスクロールを確認するCIを追加。
- 認証とFirestoreはローカルのテスト用エミュレーターだけに接続し、本番データやAI APIにはアクセスしません。
